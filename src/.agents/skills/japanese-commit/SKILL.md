# 日本語のコミットメッセージ

コミット対象の差分と実際の検証結果に基づいて、後から変更の意図を理解できるメッセージを書く。ユーザーやプロジェクトが言語・形式を指定している場合は、その指定を優先する。

## メッセージの形式

- 件名は日本語で変更の要点を簡潔に書く。リポジトリで `fix:` や `docs:` などの接頭辞を使っている場合は、その慣例を保つ。識別子・コマンド・製品名は無理に翻訳しない。
- 件名の後に空行を入れ、本文を複数行で記載する。小さな変更でも本文を付けるが、行数を増やすための重複や定型文は書かない。
- 本文には具体的な変更内容とその理由、実施した検証と結果を書く。箇条書きを使ってよい。未実施の検証や制約があれば明記し、成功したと扱わない。
- 差分や作業記録で確認できない効果・背景・テスト結果を創作しない。会話の経緯よりも、変更後の振る舞いと判断理由を残す。

例（検証内容は実際に行ったものに置き換える）:

```text
docs: 日本語コミットの記述方針を追加

- 件名と複数行の本文で変更内容・理由・検証結果を残すスキルを追加
- 作業完了時に利用できるよう AGENTS.md からスキルを参照
- 検証: スキルの形式検証と git diff --check が成功
```

## コミットへの適用

- コミットの可否、対象の分離、検証は作業先の指示に従う。このスキルだけを根拠に、コミット・push・amend を許可されたと解釈しない。既にコミットが許可されている場合は、追加確認を求めない。
- ステージ済み差分を確認し、メッセージが今回のコミット対象だけを説明していることを確かめる。
- メッセージは実際の改行を含む一時ファイルに安全に書き込み、`git commit -F <メッセージファイル>` で渡す。シェル展開や文字列のエスケープで本文が変わらないようにする。一時ファイルはリポジトリの外に作成し、使用後に削除する。
- コミット後に `git log -1 --format=%B` で件名・空行・本文を確認し、最終報告に短いコミットハッシュと検証結果を含める。
