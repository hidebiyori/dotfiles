# ライセンスの共通方針

自作のプログラムコードは、公開・非公開を問わず **GNU General Public License v3.0 only**
（`GPL-3.0-only`）を基本とする。コードを改変して配布する場合にも、受け取った人がソースを入手し、
改変・再配布できる条件を引き継ぐため。理由と代替案は [判断記録](adr/0005-license-policy.md) を参照する。

この方針は自作コードを対象とする。文章・画像・レシピ・利用者の投稿などは、コードと同じ条件で
再利用を許すものとは限らない。第三者のコードや素材の権利も本人が一方的に変更できない。
適用範囲と個別の条件は、各リポジトリで明確にする。

## GPLv3 でできること・必要なこと

- 利用・改変・商用利用ができる。私的または組織内での利用や改変だけで、ソースの公開義務は生じない。
- 改変版を配布する場合、受け取った人に GPLv3 の条件と、対応するソースを入手・改変・再配布する権利を渡す。
  ソースの提供方法やライセンス・著作権表示の保持は、配布形態に応じて GPLv3 の本文を確認する。
- ソースをインターネット上の誰にでも公開したり、変更を元の作者に送り返したりする義務ではない。
- サーバー上で改変版を動かし、ネットワーク越しに利用させるだけでは、通常 GPLv3 の配布に当たらない。
  改変したサーバーソフトウェアのネットワーク利用者にもソースを提供したい場合は AGPLv3 を検討する。
  ブラウザー等にコードを配る場合は、その配布に伴う条件も別途確認する。

非公開リポジトリにライセンスを置いても、リポジトリ自体が公開されるわけではない。
ただし、対象コードを受け取った人には GPLv3 の条件に従う再配布の権利がある。
ライセンスはアクセス制限や、個人データ・秘密情報の管理の代わりにならない。
[GNU GPL FAQ](https://www.gnu.org/licenses/gpl-faq.en.html) と
[GNU AGPLv3](https://opensource.org/license/agpl-3.0) を参照する。

## 配置と適用範囲

1. 自作コードの権利、既存のライセンス・著作権表示、取り込んだコードや素材の出典・条件を確認する。
   Codex 等を使ったことや Git の作者名だけで、第三者の権利がないと判断しない。
2. リポジトリのルートに GPLv3 の全文を `LICENSE` として置く。すでに同じ全文があれば維持する。
   文書中心のリポジトリでコードが一部のディレクトリだけにある場合は、そのディレクトリ内に置いてもよい。
   全文は書き換えず、適用範囲・例外は README 等で説明する。
3. README で `GPL-3.0-only` の対象を明記し、第三者のコード・素材や、文章等の対象外の内容を区別する。
   他の表示やパッケージのメタデータがある場合は、実際に配布する範囲と矛盾しないよう確認する。
4. 第三者の条件や必要な表示を保持し、配布時は依存関係・同梱物を含めて両立性と必要な通知を確認する。
   確認できないものは自作と断定せず、対象や条件を明確にしてから適用する。

`only` は GPL バージョン3だけを示し、将来のバージョンも選べる `GPL-3.0-or-later` とは異なる。
GPLv3 の全文にある「後のバージョンも選べる」という適用例は、各プロジェクトがそう指定した証拠ではない。
ルートの `LICENSE` の検出結果だけで、対象範囲や `only` / `or-later` を判断しない。
[SPDX の識別子と説明](https://spdx.org/licenses/GPL-3.0-only.html)、
[GitHub のライセンス配置・検出](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository) を参照する。

## 既存の条件を変更するとき

既存のライセンス、著作者と利用した外部コードを確認し、変更する権限と新しい条件の対象を確認する。
MIT 等から GPLv3 に変更しても、以前の条件で既に受け取った版をその条件で使う権利は取り消せない。
他者の権利や許諾を勝手に変更せず、第三者の表示・条件は維持する。
判断が難しいものは適用範囲を確定したように記載せず、個別に確認する。
