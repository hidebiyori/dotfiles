# 外部リンクのリファラは共有範囲に合わせて制御する

- 日付: 2026-11-06
- 状態: 採用

## 背景

リンクを開くときのリファラには参照元の情報が含まれ、設定によってはサイトのオリジンも移動先へ伝わる。
個人・家族向けや非公開の内容と、公開情報だけを扱うページでは、その情報を送る必要性が異なる。
外部画像やAPIなど、リンク以外の通信にも個別のプライバシー・連携要件がある。

## 判断

個人・家族向けのサービスや非公開の内容を扱う画面から外部へ移動するときは、リファラを送らない。
公開情報だけを扱うページでは、一律に非送信を求めず、利用目的と扱う情報に合わせて判断する。
リンク以外の通信の保護も必要な場合は、対象と既存の外部連携への影響を確認して設定する。
具体的な指定と確認方法は [共通方針](../web-app-candidates.md#外部リンクとリファラの共通方針)に記す。

## 代替案と理由

- すべてのページや外部通信を一律に非送信にする案は、公開ページの用途や参照元を必要とする連携を個別に判断できないため採らない。
- 共有範囲にかかわらず送信を許す案は、個人・非公開の利用に必要のない参照元の開示が残るため採らない。
- `nofollow` は検索エンジン等に対するリンクの扱いを示すもので、リファラの制御には使えない。

## 影響

既存の外部リンク、動的な表示とキャッシュ、配信ヘッダーをそれぞれ確認する。
リファラの非送信は移動先URLやIPアドレスの非開示を保証しない。サイト全体の設定を変える場合は認証・API等への影響も確認する。
