# オフライン起動・閲覧は任意の検討候補とする

- 日付: 2026-10-29
- 状態: 採用（任意候補として扱う方針のみ。導入の採否はアプリごと）

## 背景

オフライン対応は利用場面によって価値が異なり、実装後もCI・対象ブラウザー・公開版更新を検証・保守する負担がある。
表示中の通信失敗への対応、通信なしの再起動、書き込みの同期は、それぞれ必要な保存内容と検証が異なる。
本文のキャッシュだけでは画面の起動に必要なファイルが足りない場合があり、閲覧できても保存・同期まで安全に行えるとは限らない。

## 判断

オフライン起動・閲覧は、必要性と実装・検証・保守の負担を見て、可能なら検討する任意の候補とする。
全アプリの必須要件や着手予定にはせず、既存アプリの未対応を必須の修正事項としない。
検討を進める場合は、通信失敗からの復帰と区別して採否を決める。
閲覧対応と書き込み・再送・競合解消も分けて判断する。必要なアプリでは保存済み内容の起動・検索・閲覧から範囲を決め、
書き込みを採用していない操作は接続と権限の確認後に行う。全アプリへのService WorkerやPWAの導入は要求しない。

## 代替案と理由

- 全アプリの必須対応とする案は、利用価値と検証・保守の負担を個別に確認する必要があるため採らない。
- 本文のキャッシュだけで対応済みとする案は、ブラウザーを起動し直した後の利用を確認できないため採らない。
- 閲覧と書き込み同期を一括導入する案は、再送の重複・競合・権限失効の扱いを別に決める必要があるため一律には採らない。
- 常にオンラインだけで使う案も、用途や外部処理への依存に応じた選択肢として残す。

## 影響

採否の判断と、採用時の保存範囲・準備完了・期限・権限・更新・検証環境は、[共通の検討事項](../web-app-offline.md)を参照する。
導入する場合は保存済み画面の優先表示と[表示位置の安定](0001-stable-display.md)を維持する。
共通文書の追加で既存アプリを一括変更したとは扱わない。
