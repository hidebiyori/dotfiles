# Codex の共通指示とスキル

## 情報を置く場所

| 場所 | 管理する内容 |
| --- | --- |
| `src/.codex/AGENTS.md` | 全プロジェクトに共通する行動規則と、必要時に読む手順への参照 |
| [`docs/learnings.md`](learnings.md) | 会話・検証から得た共通知見の採用条件、公開前確認、短い判断基準と参照先 |
| dotfiles の `docs/` | 複数プロジェクトで再利用する操作・調査手順。非公開プロジェクトの名前・パス・設定値を含めない |
| 各プロジェクトの `AGENTS.md` | そのプロジェクトの検証コマンド、構成、公開時の注意点 |
| 各プロジェクトの文書・設定 | Firebase のプロジェクト ID、Hosting target、workflow、公開先など |

README は利用者向けの入口とし、詳細手順の本文は目的別の文書にまとめる。
共通指示には、安定した動作に必要な判断規則を残す。解決済みの不具合や作業の経緯は Git の履歴で確認する。
認証情報の値はどの文書にも保存しない。

Firebase 公開認証の手順は **グローバル配布用の `src/.codex/AGENTS.md` から
`~/git/dotfiles/docs/firebase-deploy-auth.md` を参照している**。
Chrome / Playwright の接続手順も同様に参照する。
対象の作業時に手順を読み、実際のプロジェクト設定と権限を確認する。
個別プロジェクトの認証方式・公開先は、そのプロジェクト内に記載する。

[公式の指示ファイル読み込み順](https://learn.chatgpt.com/docs/agent-configuration/agents-md)では、
グローバル指示にプロジェクト内の指示を重ねる。同じ階層の `AGENTS.override.md` が優先される。

## 会話から得た知見の反映

共通指示から [共通知見](learnings.md) を参照し、作業に必要な項目を読み、
作業の区切りに再利用できる知見を抽出・統合する。
ユーザーが共通方針として明示した内容や、適用条件を確認できた事実を対象にする。
公開する前に、本文・リンク・コード例・コミット・PR から非公開の対象を特定できないか確認する。

これは各作業で行う文書更新で、定期実行や過去の全チャットの自動収集は設定しない。
`learnings.md` 自体は指示ファイルとして自動読み込みされないため、共通指示を配置・同期して利用する。

## Windows と WSL の定期タスク

ローカルの定期タスクは、実行時にPCとデスクトップアプリが起動し、対象の作業場所にアクセスできる必要がある。
「有効」や次回予定の表示だけでは、過去の実行や作業の完了を確認できない。
実行履歴に加え、作成されたスレッドに指示と結果があるか確認する。

Windows アプリから WSL 上のプロジェクトに対して毎回新しいスレッドを作るタスクでは、
Windows 形式のパスを WSL 側へ渡した際に起動が失敗し、結果のない実行が進行中に見える事例がある。
`AbsolutePathBuf deserialized without a base path` が出る場合は、この
[公開Issue](https://github.com/openai/codex/issues/27567)と照合する。
同じスレッドを再開するタスクの成功だけでは、新しいスレッドを作るタスクの成功を証明できない。

アプリの再起動で表示が変わっても、実際の起動と完了を確認するまで解消とは扱わない。
毎回新しいスレッドを作らなくてもよい場合は、新たに通常のスレッドを作り、毎回そのスレッドを再開する方式を試せる。
作業内容・曜日・時刻・通知設定を維持し、モデル設定が変わる場合は利用者に確認する。
切り替え後は、ファイル操作や外部通信をしない一時診断で、対象の各スレッドが通知を受け取り応答するか確認する。
アプリの更新後に新しいスレッドを作る方式も安全な実行で再確認する。
内部データベースや保存ファイルを直接書き換えたり、利用者が指定した実行方式を無断で変えたりしない。
ログの確認時は認証情報や本文を出力せず、対象の時刻・タスク・エラーの要約に限る。

## Codex のスレッドが見つからないとき

通知やリンクからチャットを開けないときは、まず同じスレッドが接続先の PC に残っているか確認する。
通知から開いた結果と、アプリ内のタスク一覧から開いた結果をそれぞれ確認する。

### Android のタスク一覧を確認する

1. ChatGPT アプリの「Codex」または「Remote」から、作業を実行した PC を選ぶ。
   タスク一覧で絞り込みを解除できる場合は解除する。
   一覧の読み込みが終わったらタイトルを探す。
2. PC 本体で同じタイトルやスレッド ID を探し、最後のやり取りまで開けることを確認する。
   PC でピン留めした場合は、Android でもその PC の一覧にピン留めが表示されるか確認する。
   別の接続済み端末があれば、同じ PC とスレッドの表示を比べる。
3. 一台の Android だけで見えない場合は、ChatGPT アプリを開き直す。
   改善しなければ、Android の設定で「アプリ」→「ChatGPT」→「強制停止」を選ぶ。
   その後はアプリアイコンから起動し、同じ PC の一覧を確認する。
   続く場合は、Android の設定で「アプリ」→「ChatGPT」→「ストレージとキャッシュ」→
   「キャッシュを削除」を試す。削除対象は端末の一時データで、設定の表示名は機種によって異なる。
4. Android で同じ PC の一覧に戻り、対象のスレッドから本文を開けることを確認する。
   PC で本文を読める間は、PC から作業を再開できる。
   `codex://threads/…` はデスクトップ用のリンクで、Android ではアプリ内の一覧から探す。

PC が接続先に出ない場合は、両端末のアカウントとワークスペースを確認する。
PC がオンラインで起動中で、デスクトップアプリのリモート接続が有効かも確認する。
[OpenAI のリモート接続手順](https://learn.chatgpt.com/docs/remote-connections#troubleshooting)。
[Google のアプリのキャッシュ削除手順](https://support.google.com/pixelphone/answer/9454904?hl=ja)。

### PC のタスク一覧で見つからないとき

1. 通常の一覧とアーカイブを確認する。
   対象がアーカイブにあれば、同じタイトルや ID を確認してアーカイブを解除する。
2. Windows と WSL を切り替えた後なら、両方の履歴を確認する。
   既定の保存先は、Windows アプリでは `%USERPROFILE%\.codex`、WSL 内の CLI では `~/.codex`。
   `CODEX_HOME` を設定している場合は実際の値を確認する。
   CLI の履歴にあれば、その環境で `codex resume <スレッドID>` を使って再開できる。
3. 一覧で判断できない場合は、利用できる Codex の履歴検索機能で通常とアーカイブを全ページ確認する。
   App Server では `thread/list` の `archived` を切り替え、`nextCursor` がなくなるまで取得する。
   ID が分かる場合は `thread/read` や履歴の取得機能で、対象と最後のやり取りを確認する。

バックアップからの復元が必要な場合は、現在の履歴も先に別の場所へバックアップする。
稼働中の SQLite は SQLite のバックアップ機能を使ってコピーする。
既存の履歴との統合は、別の検証環境でスレッド ID、最新のやり取り、既存の履歴を照合してから行う。
[Windows と WSL の保存先](https://learn.chatgpt.com/docs/windows/windows-app#windows-subsystem-for-linux-wsl)。
[Codex CLI の再開](https://learn.chatgpt.com/docs/cli/reference#codex-resume)。
[Codex App Server の履歴取得](https://learn.chatgpt.com/docs/app-server)。

表示の問題が続く場合は、通知の時刻、アプリのバージョン、接続先、別端末での表示結果を控える。
サポートに伝えるときは、どの経路で一覧や本文が開けたかを添える。
会話の本文や認証情報は記録に含めない。

## 配置と同期

`bin/install.sh` は `src/.codex/AGENTS.md` を `~/.codex/AGENTS.md` へリンクする。
`CODEX_HOME` があれば、その絶対パスにもコピーする。
WSL で未指定なら Windows 側の `CODEX_HOME`、次に `%USERPROFILE%\.codex` をコピー先に使う。
Windows アプリ用には通常ファイルを配置する。認証・履歴・その他の設定は同期しない。

**編集先は `src/.codex/AGENTS.md`。Windows 側のコピーは編集・pull だけでは更新されない。**
`u` で再適用するか、パッケージ更新を伴わない次のコマンドを WSL 内で実行する。
独自の `CODEX_HOME` がある場合は対象アプリと同じ保存先を指定しておく。

```bash
bash -c 'source "$HOME/git/dotfiles/bin/install.sh"; setOptions; setCodexInstructions'
```

このコマンドは現在のチェックアウトからコピーし、リポジトリの取得・更新はしない。
指示の読み込みには新しいセッションを開始する。
WSL 内の Codex CLI の既定保存先は `~/.codex` で、Windows アプリとは別になる。

## 共通スキル

自作スキルは `src/.agents/skills/<skill-name>/SKILL.md` に置き、セットアップで
`~/.agents/skills` 以下へファイル単位でリンクする。
dotfiles 自身を作業するときは、チェックアウト内の `src/.agents/skills/<skill-name>/SKILL.md` を原本として参照する。
`~/.agents/skills` はセットアップ後の配置先なので、未配置の環境でも原本はリポジトリ内から読める。

- `japanese-commit`: 日本語の件名と複数行の本文に変更内容・理由・検証結果を書く。
- `npm-vulnerability-remediation`: Dependabot の検知を確認し、対象を絞って依存更新・検証する。

スキルの Python 検証には[共通の仮想環境](development-tools.md#スキル用-python)を使う。
スキルを削除・改名した場合は、配置先に残る古いリンクも削除する。
